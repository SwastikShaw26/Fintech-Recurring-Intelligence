## Executive Summary

An exhaustive, evidence-based code and security audit was conducted on the FinSight codebase across five dimensions:
1. **Functional Correctness**
2. **Algorithm Reliability & Statistical Validity**
3. **Architecture, Modularity & Maintainability**
4. **Security, Privacy & Supply-Chain Integrity**
5. **Testing Coverage & Evaluation Gaps**

While FinSight provides a remarkably disciplined, functional prototype with a clean editorial design and zero ML bloat, the audit uncovered significant risks:
- **Critical Evaluation Circularity**: The 100% benchmark score is circular. Heuristics in `detect_recurring_v3.py` are overfitted to the 8 exact merchants in `generate_dataset.py` with zero holdout test split.
- **Fragile Hardcoded Boundaries**: Calendar month assumptions (strictly 28–31 days) break across realistic billing cycles, leap years, and bank settlement delays.
- **CORS Wildcard & No Rate Limiting**: Backend is exposed via `allow_origins=["*"]` without auth, rate-limiting, or CSRF protection.
- **Unused Dependency Overhead**: `recharts` (3.x) and Tailwind CSS are bundled in `package.json` and production assets, but `recharts` is entirely unused in `App.tsx` and custom CSS is used instead of Tailwind.
- **Synchronous CSV Disk I/O**: High contention risk under concurrent requests due to repetitive disk reads and linear complexity.

## 2. Algorithm Reliability & Evaluation Weaknesses

### 2.1 The "100% Accuracy" Trap (Data Leakage & Overfitting)
- **Zero Train/Test Split**: `src/evaluate_detector_v3.py` evaluates `transaction_predictions.csv` against `data/raw/ground_truth_labels.csv`, which was generated by `src/generate_dataset.py` with static, deterministic intervals (`[0, 31, 59, 90, 120]`).
- **Hardcoded Constants Tuned to Synthetic Dataset**:
  ```python
  # detect_recurring_v3.py
  CADENCES = {
      "monthly": (28, 31),
      "quarterly": (85, 95),
      "annual": (350, 380),
  }
  ```
- **Edge Case Failures in Real-World Indian Banking**:
  1. **Delayed Settlement Gaps**: A debit initiated on Friday the 28th that settles on Monday the 1st or 2nd can result in a 32–34 day interval. Under `detect_recurring_v3.py`, `low <= typical_interval <= high` fails for monthly, misclassifying genuine monthly commitments as `irregular` or `none`.
  2. **February & Month-End Variations**: A monthly subscription billed on the 31st of March, 30th of April, 31st of May produces intervals of 30, 31 days. But billing from Jan 31 to Feb 28 produces a 28-day gap, and Feb 28 to March 31 produces a 31-day gap. While (28, 31) covers standard months, a billing delay of 1 day (32 days) drops interval consistency below 0.5.
  3. **GST & Dynamic Surcharges**: Many Indian subscriptions fluctuate due to GST rate changes or consumption surcharges (e.g. cloud storage or telecom plans changing by 2–5%). In `detect_recurring_v3.py:156`, `amount_spread > 0.05` switches the classification to `variable`, but if spread exceeds 10%, `cadence = None` and the entire subscription is rejected!

## 3. Architecture & Code Hygiene

### 3.1 Component Boundaries & Data Substrate
- **Synchronous CSV Disk Access (`src/api.py`)**:
  - `load_transactions()` and `load_commitments()` read and parse CSV files directly on **every single incoming HTTP request**.
  - `make_commitment_id` generates SHA1 hashes on the fly for every row.
  - Linear scan complexity: As transaction history scales to thousands of records, `/api/transactions` and `/api/commitments` will suffer severe latency degradation.
  - Concurrency Hazard: If `detect_recurring_v3.py` is invoked while `api.py` is serving a request, `api.py` reads partially written CSV files, throwing unhandled `csv.Error` or `ValueError`.

### 3.2 Frontend & Backend Integration
- **State Synchronization**:
  - The frontend (`frontend/src/App.tsx`) fetches all endpoints independently inside a single `useEffect`.
  - There is no client-side caching (e.g., TanStack Query or SWR), leading to layout shifts and redundant requests on page navigation.
- **Dead Code & Unused Packages**:
  - `frontend/package.json` imports `recharts` (3.10.1), `@tailwindcss/vite` (4.3.3), and `tailwindcss` (4.3.3).
  - Neither Tailwind nor Recharts is imported or used in `App.tsx` or `App.css`. `App.css` contains an entirely custom CSS variable system. These unused packages needlessly bloat `node_modules` and frontend build artifacts.

## 4. Security, Privacy & Vulnerability Analysis

Applying the `security-review` checklist:

### 4.1 CORS Misconfiguration
- **Vulnerability**: `src/api.py:32-38`
  ```python
  app.add_middleware(
      CORSMiddleware,
      allow_origins=["*"],
      allow_credentials=True,
      allow_methods=["*"],
      allow_headers=["*"],
  )
  ```
- **Impact**: In a multi-origin environment, allowing wildcard `*` with `allow_credentials=True` permits any malicious website opened in the user's browser to execute authenticated cross-origin requests to local fintech APIs.
- **Remediation**: Restrict `allow_origins` to explicit local development origins (`http://localhost:5173`, `http://127.0.0.1:8000`).

### 4.2 Denial of Service / Resource Exhaustion
- **Vulnerability**: `/api/transactions` accepts `limit: int = Query(default=100, ge=1, le=1000)`. Because transactions are parsed from CSV in memory on every request, rapid repeated requests with `search` parameters perform unindexed regex/casefold scans over all rows without rate limiting.
- **Remediation**: Introduce an in-memory SQLite store or cache layer with basic request throttling (e.g., `slowapi`).

### 4.3 Sensitive Financial Data Handling & PII
- **Positive Findings**:
  - `synthetic_transactions.csv` contains purely synthetic, non-PII test records.
  - `reference_id` is anonymized and never assumed to be a bank mandate or card number.
  - `cancellation_guide.py` explicitly issues disclaimers stating that FinSight cannot execute cancellations or connect directly to bank accounts.
- **Gap**: There is no data sanitization filter to prevent real PII/account numbers from leaking into `transaction_evidence` strings if a user uploads a live statement.

## 5. Testing & Verification

### 5.1 Test Suite Status
- **Test File**: `tests/test_api.py`
- **Scope**: 11 API integration tests using FastAPI `TestClient`.
- **Gaps Identified**:
  1. **Zero Unit Tests for Algorithmic Detection**: No test directly exercises `detect_recurring_v3.py`, `split_streams()`, or `classify_intervals()` with adversarial edge cases (e.g. leap years, 33-day gaps, negative amounts, zero amounts).
  2. **Missing Property-Based Tests**: Invariants such as "sum of debit predictions + credit transactions == total transactions" and "confidence score is always $\in [0, 1]$" are not verified with property tests (`hypothesis`).
  3. **No Frontend Component or E2E Tests**: Zero Playwright or Vitest tests exist in `frontend/`.

## 6. Prioritized Remediation Recommendations

| Priority | Component | Recommendation | Impact |
|---|---|---|---|
| **P0** | Algorithm | Expand cadence tolerance windows (e.g. monthly 27–34 days) and support date-based calendar month matching rather than strict day-count intervals. | Prevents false negatives on month-end billing drift. |
| **P0** | Security | Tighten CORS policy from wildcard `*` to configured local origins. | Prevents cross-origin exploitation. |
| **P1** | Testing | Add property-based and adversarial tests for `detect_recurring_v3.py` using `hypothesis` and held-out scenarios. | Validates true algorithmic generalization. |
| **P1** | Performance | Transition runtime CSV reads in `src/api.py` to an in-memory cache or lightweight SQLite database. | Eliminates synchronous disk I/O bottleneck. |
| **P2** | Dependency | Remove unused `recharts` and `tailwindcss` from `frontend/package.json`. | Reduces bundle size and dependency surface. |
| **P2** | Normalization | Implement flexible substring and regex normalization in `config/merchant_aliases.json` rather than strict exact matching. | Robust descriptor resolution. |
