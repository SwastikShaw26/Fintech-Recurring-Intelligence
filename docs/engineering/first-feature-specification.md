## 1. Feature Definition

### 1.1 The Problem
1. **Security Vulnerability (`src/api.py`)**: The FastAPI server configures `allow_origins=["*"]` alongside `allow_credentials=True`. This allows arbitrary web pages in the user's browser to execute authenticated cross-origin requests to local fintech endpoints.
2. **Dead Dependency Bloat (`frontend/package.json`)**: `recharts` (3.x) and `tailwindcss` (4.x) are installed in dependencies and devDependencies, adding ~600KB of dead bundle weight, even though `frontend/src/App.tsx` has no Recharts component and `App.css` uses raw CSS custom variables.
3. **Circular Evaluation / Benchmark Trap (`src/evaluate_detector_v3.py`)**: The current 100% precision and recall metrics are circular: the detector's heuristics (`detect_recurring_v3.py`) are hardcoded to match the exact 56 transactions generated by `generate_dataset.py`. There is no holdout split, no adversarial noise (weekend settlement drift, bank holidays, GST rate variations, or noisy UPI descriptor tags), and no property tests.

### 1.2 Expected Behavior
- **Secure API**: Requests originating from unauthorized origins receive `403 Forbidden` or no CORS headers; authorized localhost origins (`http://localhost:5173`, `http://127.0.0.1:8000`) succeed with `200 OK`. Query parameters on `/api/transactions` enforce safe bounds.
- **Clean Frontend**: `recharts`, `tailwindcss`, and `@tailwindcss/vite` are removed. `npm run build` succeeds cleanly with smaller bundle size and zero UI regressions.
- **Independent Evaluation Suite**:
  - `src/generate_dataset.py` is extended to generate two cleanly decoupled datasets:
    1. `data/raw/synthetic_transactions.csv` & `data/raw/ground_truth_labels.csv` (Standard 56-row baseline).
    2. `data/raw/holdout_transactions.csv` & `data/raw/holdout_ground_truth_labels.csv` (New 150+ row adversarial dataset with weekend settlement drift, month-end clamps, GST adjustments, and noise transactions).
  - A standalone test script `tests/test_adversarial_benchmark.py` evaluates the detector against the holdout set, reporting true generalized Precision, Recall, and F1.

### 1.3 Intended Users & Scope
- **Users**: FinSight engineers, judges, and auditors who require verified accuracy metrics and safe execution.
- **Scope**: Modifies `src/api.py`, `frontend/package.json`, `frontend/vite.config.ts`, `src/generate_dataset.py`, and creates `tests/test_adversarial_benchmark.py`. Does **NOT** alter the core detection logic in `detect_recurring_v3.py` yet (that is Phase 1).

### 3.2 Dataset Specification: Adversarial Holdout Scenarios

The new holdout generator (`generate_holdout(seed: int = 101)`) will produce 150+ transactions across 12 distinct scenarios:

1. **Weekend Settlement Drift (Monthly Recurring)**:
   - Schedule: 1st of month. Gaps: `[0, 31, 33, 29, 32]` (simulating Friday debits settling on Monday). Amount: ₹299.00. Expected: `is_recurring = True`, `cadence = "monthly"`.
2. **Month-End Leap & Short Month Drift**:
   - Jan 31 $\to$ Feb 28 $\to$ Mar 31 $\to$ Apr 30 $\to$ May 31. Gaps: `[0, 28, 31, 30, 31]`. Amount: ₹499.00. Expected: `is_recurring = True`, `cadence = "monthly"`.
3. **GST Rate Fluctuation (Price Creep / Tax)**:
   - Base ₹1000 + 18% GST vs base ₹1000 + 0% GST (e.g. ₹1000, ₹1180, ₹1180). Expected: `is_recurring = True`, `review_required = True`.
4. **Noisy UPI Descriptor Variations**:
   - Same merchant (`CloudNest`) with descriptors: `UPI/CLDNST/8372/SUB`, `POS 99 CLDNST BANGALORE`, `CLDNST RECURRING DEBIT`. Expected: Grouped as single merchant.
5. **Adversarial Non-Recurring Habitual Spending**:
   - Coffee / Cab transactions: `STARBUCKS COFFEE` with gaps `[0, 2, 7, 14, 21, 28, 35]` and varying amounts (`[250, 320, 250, 410, 250]`). Expected: `is_recurring = False`.
6. **Quarterly Settlement Drift**:
   - Quarterly subscription with gaps `[0, 92, 89, 94]`. Expected: `is_recurring = True`, `cadence = "quarterly"`.

## 5. Testing & Verification Strategy

### 5.1 Unit & Integration Tests
- **CORS & API Security Test**:
  - Test GET `/api/summary` with header `Origin: http://localhost:5173` $\to$ Assert `Access-Control-Allow-Origin: http://localhost:5173`.
  - Test GET `/api/summary` with header `Origin: http://evil-tracker.com` $\to$ Assert header `Access-Control-Allow-Origin` is **omitted** (or blocked).
- **Holdout Dataset Integrity Test**:
  - Verify `holdout_transactions.csv` has 0 duplicate transaction IDs, valid ISO dates, positive amounts, and matching labels in `holdout_ground_truth_labels.csv`.
- **Detector Baseline Measurement**:
  - Run `src/detect_recurring_v3.py` against the holdout data.
  - Record and document the raw, honest baseline scores before any Phase 1 heuristic changes.

## 7. Risk Assessment & Mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| **CORS break on remote dev server** | Low | Include both `127.0.0.1` and `localhost` with ports `5173` and `8000`. |
| **Frontend build break on Tailwind removal** | Low | Verified in `UI_AUDIT.md` and `App.css`: no Tailwind classes or directives (`@apply`, `@theme`) are present in `App.css`. |
| **Detector scores collapse on holdout set** | High (Expected) | **This is the goal**. A lower initial score on adversarial data exposes the true vulnerabilities (e.g. 33-day settlement gaps), setting up a verifiable baseline for Phase 1. |
| **Rollback Plan** | Very Low | Changes are isolated to configuration, dependencies, and test generation. Git rollback is clean and instant. |
